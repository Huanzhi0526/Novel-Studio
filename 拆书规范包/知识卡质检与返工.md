# 九类制卡与验收

每张卡围绕一个清楚的对象或写作参考问题。读者只打开这张卡，也应看得懂主体、范围、关键变化和依据。各类共用 `NKS draft-0.1` 字段，栏目写在可换行的 `content` 中。

## 用公开资料起稿，再用同版正文核实和补充

优先查同一版本的作者、出版社简介和人物页，用百科、贴吧、论坛、介绍视频补充角色、关系、梗概、转折、术语和读者常用说法。可用的信息先纳入对象提纲，附链接、版本和涉及的卷章。已获原文印证的内容用自己的话写进卡片。Agent 独立阅读和总结，补上资料省略的选择、变化、例外和结果。找不到可用资料时，从原文建同样的提纲。对读者解读、人物说法、假设路线和事实分别标明来源或性质。

卡片里的每项实质主张都要有明确落点。`[1]`、`[2]` 依次对应 `evidence`。跨卷主张要分别引用转变前、触发点和后续结果。外部 URL 和视频时间点保留在研究记录。卡内证据坐标来自派工指定的正文版本。确实缺证时记录为待核，卡面以已确认的范围为准。

## 九类的卡片内容

| 类别 | 一张可用的卡片应写什么 |
| --- | --- |
| 人物 `character` | 姓名、身份和叙事定位、性格和动机、矛盾与代表行为、关键关系的前后变化、主要选择与代价。用一小段串起这个人的经历，标出截至何处。有依据的贵族大小姐、男性主角等身份或定位可自然出现在开头。 |
| 设定 `setting` | 哪条世界规则、制度或习惯，在什么范围有效，谁受影响，怎么实施，有哪些可观察的后果、修订或例外。 |
| 力量体系 `power_system` | 谁能用、取得或发动的条件、效果、消耗、上限、失败或相克情况，用一次具体表现把规则和代价说明白。 |
| 组织 `organization` | 组织目标、成员与权力结构、日常如何运作、资源与手段、关键盟友或对手，以及局势如何改变。 |
| 事件 `event` | 触发原因、有关各方和利害、转折中的选择、直接结果与后续影响。以一个可命名的事件为范围。 |
| 故事线 `storyline` | 一条持续推进的冲突或目标，如何开始、升级、转向和收束，各阶段的因果及当前进展。 |
| 地点 `location` | 位置、进入方式、空间特征、用途、管理或限制。写清空间如何影响人物行动或场景安排。 |
| 物品 `item` | 物品归属或来历、用途、使用条件、限制或代价、流转和实际后果。 |
| 写作技巧 `technique` | 某一段怎样安排视角、信息、节奏、伏笔或对照。描述具体文本做法与效果，指出在什么情形下可参考。 |

主角、重要对手及关键配角先写人物档案。开头可用「身份和处境」「叙事定位」几句概括，正文再用「性格与动机」「重要关系」「关键选择与角色线」分段。局部事件只有独立用途时再成卡。次要对象可以写得短。没有合适卡的类别按实际覆盖说明原因。

## 轻量格式与重点

`title` 保持纯文本，`content` 使用受限 Markdown。先写一小段概括，再按对象安排二级或三级小标题、短段落、无序列表或简单有序列表。人物关系、能力条件和跨卷阶段可以逐项列出。证据编号 `[1]`、`[2]` 保持原样，并留在对应主张旁。

粗体用于少量关键选择、转折、条件、限制或结论。强调时保留否定词、前提和适用范围，避免改变句意。引用块只用于有必要对照的短引文，并附原文证据。卡内采用统一的小标题风格，不重复写一遍卡名和正文。

不使用 HTML、CSS、颜色代码、自定义高亮语法、图片、表格、代码围栏或外部链接。网页来源放在研究记录。卡片类别与标签分组提供语义，显示颜色由软件统一映射，Agent 负责内容和归类。纯文本历史卡继续按实际内容复核，格式整理随用户安排进行。

## 九类卡的检索标签

每张卡在概括之后用 `## 检索标签` 小节登记适用的属性，每组一行，例如 `- 身份｜贵族大小姐、公爵长女`。继续使用现有 `content` 字段，标签不新增为 JSON 字段，也不塞进 `aliases`。推荐使用下表中的分组名称，按证据选用，缺少依据的属性不填。

| 类别 | 优先检查的标签分组与内容 |
| --- | --- |
| 人物 | 叙事定位、身份、职业、性格、关系、能力。分别检查男主或配角定位、头衔与阶层、职责、行为特点、人际身份和能力特征。 |
| 设定 | 机制、适用范围、限制、例外、主题。标出规则作用于谁、在何处生效及其后果。 |
| 力量体系 | 能力、条件、效果、限制、代价、相克。用实际发动和失败条件组织检索词。 |
| 组织 | 职能、权力结构、手段、关系、目标。区分组织身份与成员个人头衔。 |
| 事件 | 情节机制、冲突、反差、转折、结果、场景。说明对立怎样建立、人物采取什么行动、如何反转及谁的判断改变。 |
| 故事线 | 目标、冲突、阶段变化、关系、主题。覆盖长期推进和阶段性收束。 |
| 地点 | 场景、空间、用途、进入条件、限制。关注空间如何影响行动。 |
| 物品 | 用途、归属、条件、限制、代价、流转。保留实际名称及常用查找描述。 |
| 写作技巧 | 手法、叙事效果、适用情境、限制。标注可分析的文本做法及其作用。 |

同义词、上位词和常见问法可以并存，例如「男主、男性主角、男主人设」。完全重复的词在同一组中去重，标签应保持可读。名字、译名、绰号和实际称呼仍用 `aliases` 收录。百科等公开页面的标签可以作为候选，登记来源后回同版原文核对。分析性标签在卡面标明性质，并在复核记录说明依据。

「打脸」应有先前轻视或质疑被后来的事实反转的依据；「装逼」应有实力或身份的展示及他人反应；「扮猪吃虎」应核对隐瞒实力、对手误判与反转过程。普通战斗胜利本身不足以支持这些标签。保留具体机制描述，让口语词和自然语言问法都能找到线索。

## 有既有卡片时的处理

若本次派工附有需要整理的卡片，先审阅卡片和对象，再核对章节覆盖。内容已充分时补适用标签和检索描述，概括过粗时补充具体桥段与证据，有独立查找价值时新增专题或事件卡。未制卡的内容需回原文补卡。更新原卡沿用 `card_id`，同版正文沿用卷、版本和段号。

标签与排版整理、正文核读、漏项补卡分别记录完成情况。未读范围继续按实际登记，格式更新不构成整书核读完成。具体书目、缺章和剩余工作以该次派工回执为准。

## 怎样验收

1. 只看标题、类型和首段，应认得出对象并看懂查找价值。标题具体，名字和译名用 `aliases` 收录。身份和叙事定位用有证据的自然语言表述。
2. 读全卡，核查段落是否共同说明同一个对象。人物卡能据此理解角色，机制卡能说明条件及代价，事件卡能解释转折与影响。对「性格复杂」「推动剧情」等概括追问具体行为和结果。
3. 逐项核对证据。`fact` 用于可直接验证的事实，`interpretation` 用于因果、动机、人物弧线或叙事效果等推断。分析卡分开写原文可证部分和解释。保留所有重要转折的证据，区分事实、转述、传言与尚未发生的计划。
4. 写预期检索题和命中卡 ID。对「有哪些大小姐人设」这样的类型问句，逐张检查候选人物卡是否具备相应定位，并能独立比较角色的处境、行为和变化。对其他类别也准备按用途查找的问题，如「哪些能力需要付出记忆作为代价」。
5. 运行结构校验及机器筛查，再核对人工复核结果。有隔离库时复跑检索和证据跳转，记录实际排名。查询覆盖、入库版本和未验证项随报告交付。
6. 检查轻量格式、标签分组和强调范围，核对标签是否被同版证据支持。各类有卡时都准备至少一道自然问句，再补同义问法、多目标和无答案题。分开记录本地检索、API 辅助检索及待实测项。API 扩展问句与筛选结果后，仍需抽查实际卡面和原文。
