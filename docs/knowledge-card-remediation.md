2026-11-10 起暂停拆新书，优先复查已有卡。按[九类质检与返工标准](../拆书规范包/知识卡质检与返工.md)验收。主角总卡应回答身份、动机、主要关系、选择、转折和最后能核实的状态。其他类别各有自己的问题，例如力量体系应给条件、代价和反例，地点应给路线、限制和用途，技巧应指出文本怎样安排信息以及依据。标题、类别、正文和证据要指向同一个具体问题。

## 下一批怎么做

1. 用逐卡台账划定范围。先查同一人物或机制的现有卡，判断应写贯穿已入库范围的总卡，还是保留原问题的小卡。对已入库多卷作品优先修掉跨卷缺口；已有单卷作品可整卷覆盖九类，缺证的类别记明原因。
2. 需要找线索时，可先查作者或出版社的书目、简介，再查百科、文库和论坛。记录来源、版本、可信度、候选落点，回到入库版原文逐条核实。跨译本、外传和改编线索分别记录。
3. 读原文，把每条要写的主张和证据段落放在一起。用 `[1]` 等编号对应卡片中的证据，区分事实、角色自述与分析。逐卡复核内容是否回答标题和类别的具体问题。
4. 同一检索主题复用 `card_id`，引用复用原正文版本。正式库中修订号大于 1 的历史卡先保留。已经读原文核对的保护项记 `protected` 与依据。原始卡核对后保留记 `retain`。待核的内容记 `pending`，并记清缺少的证据。相近卡在台账记关系或待归并理由。
5. 先在隔离资料目录验收。运行协议校验和内容筛查，复跑时应幂等。验证每个有修改的类别能检索到对应卡，完整内容可展开，编号能打开正确版本与段落。通过后将实际写入、待修和待审数量记回台账。

## 本机维护命令

正常退出正式应用并准备隔离副本。从源码根目录运行：

```powershell
node --disable-warning=ExperimentalWarning scripts/audit-reference-cards.mjs $library "$reviewDir/inventory.json"
node --disable-warning=ExperimentalWarning scripts/revise-reference-cards.mjs --check $library $patch
node --disable-warning=ExperimentalWarning scripts/revise-reference-cards.mjs --apply $isolatedLibrary $patch "$reviewDir/before-isolated.sqlite"
```

维护补丁是含 `cards` 数组的 JSON。旧卡提供 `id`、`workId`、`cardId`、`expectedRevision: 1`、`title`、`content`、`evidence`，可提供 `claimType`、`aliases` 和 `relatedCardIds`。分类有误时可显式提供经核证的 `category`，同时记录改类原因和目标检索问题。缺失且确有独立检索价值的卡使用 `id: null`、`expectedRevision: 0`、固定 UUID、`category` 和 `claimType`。证据用 `volume_id`、`revision_id`、`start`、`end`，段号格式为 `p000001`。同一条目应有独立审阅记录。

已发布的一轮改稿需要单独改类时，先锁定已写入补丁的 SHA-256 和旧类别。维护工具只接受预期修订 2，须显式提供 `previousCategory` 和已发布的完整卡文、断言类型、别名、关联和证据。正式数据除目标类别外必须逐项相等，任何内容差异或更高修订都拒绝。含此类改动的累计补丁从已写入前置批次的数据库继续。

脚本使用应用的引用校验和写入路径，按作品与卡片身份检查，在事务里重建改动卡的关键词索引、使旧向量失效，保护已修改的旧卡。应用时要给一个全新的 SQLite 备份路径。先验收隔离应用，再对正式库应用已审批次，核对数量、完整性、手改保护及正文未变。应用内可在「资料与设置」重建本地语义索引。按 [维护说明](maintenance.md#资料和迁移) 保留正式备份。

本机续批工具在 `.local/card-remediation-next`，与单独下载的源码包分开保存。用 `remaining.mjs` 加上最近正式检查点和作品名列出未完卷次。每次冻结 Agent 交付后，先检查 `stage-next.ps1` 的目录白名单和最终稿选择，再使用新的检查点标识跑隔离写入及模型检索。运行 `installed-qa.mjs` 和数据库前后比对后，才用 `publish-local.ps1` 更新正式库。最后运行 `audit-published.ps1`，传入本次和上一次正式检查点，重跑对照、正式检索并更新逐卡台账和 CSV。应用前先核对桌面正式实例当前没有待保存的原创修改。隔离向量只有在模型、配置与写入后的卡面逐项匹配时才复用。

当前批次的实测和可续做范围见[验收记录](acceptance.md)与[项目交接](../HANDOFF.md)。
