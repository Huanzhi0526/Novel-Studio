## 给作者和主管的判断

**第一批修普通参考检索。** 参考库页与写作侧栏共用同一个入口。它们查询向量时，占用的恰好是窗口响应点击、接收取消和处理保存请求所需的主进程。旧主管修过助手查库卡死，那条路径已经独立运行。把普通入口也接好，才能让作者边查边写。无需先换向量库或重新拆书。

**第二批修反重力从点击到完成的整条链。** 设置里的“刷新列表”和“测试连接”做的是两件事。前者重新寻找 CLI 并枚举模型，后者用所在用途的客户端真实发一条固定句，可能让下一次调用省掉启动进程的时间。助手还有自己的模型目录和按书会话。把同一用途的连接准备做到首次使用里，并给每一步计时，才能知道是本机卡在准备，还是模型已经收到请求、尚未给出结果。

**第三批按实际出现的画面修卡顿。** 空库连续切页很快。优先观察“一边查库一边切页”“长章节离开写作页”“助手生成长回复”“深色启动”四种场景。作者的症状值得修，当前证据还不能把每次闪烁归到同一个按钮或样式。

## 实施顺序与合并条件

### 第一阶段　建立基准，先修普通检索和分页

1. 在隔离目录建立合成原创、三层参考条目、同卷两版、至少 13 条可入选卡、已封存书、合成向量。让 UI 的参考库、侧栏、按书助手分别走真实注册的 handler。小库验证内容，大数据集专测性能。记录基线版本、行数、维度、运行环境与数据生成种子。
2. 抽取**现有** AssistantSearch 的只读执行能力，优先沿用检索引擎。主进程持有请求取消、配置/密钥和库代次。worker 只开只读库，处理 FTS、向量评分、候选装配。API/CLI 与 embedding 通过现有消息桥调用。查询任务加有界并发，初版同刻 1 次重扫描，可取消排队，允许写作与轻量 IPC 并行。
3. 解决 worker 生命周期与游标的冲突。推荐在 worker 返回有限的排序 ID＋注释后，由主进程按请求范围、原模式、库代次保管有界分页状态，下一页只委托 worker 按固定 ID 物化；也可保留有界长期 worker，只要重启和失效有明确语义。**当前一次一 worker 会在 finish 被 terminate，直接把普通 IPC 换成现有助手对象会丢分页**。AI 失败回退产生的本地结果也要能按原请求翻页。资料变化时拒绝旧结果，恢复时先停止接受任务并 await 所有只读句柄关闭。
4. 去掉成功路径的备用全扫描，保留已取消、过期和上游失败的不同处理。避免把配置变化、用户取消当成需要再扫库的普通失败。验证成功/失败调用数、空选择、同版证据、降级原因及首页导读。先保持全量精确检索，再决定是否优化评分算法。

**完成条件**　由 UI 打开的两条普通入口和助手均能边检索边切页、保存和停止。同输入下前后卡 ID、排序、证据相同（已证明有误的分页和错版引用单独记录）。13 条分页两页并集 13、无重复、零额外生成。构建和隔离安装都找到正确 worker。

### 第二阶段　让首次调用可以直接使用

1. 建立一个共享的 CLI 发现组件，提供 `resolveExecutable`、模型目录、进程环境准备和显式刷新。采用异步路径/代理查找，按 CLI 路径、版本和用户上下文缓存成功目录，必要时短时复用。持久化只存模型元数据与验证时间，不记录账号秘密。路径消失后自动重新定位一次，并使旧客户端失效。已有选模在短时目录服务失败时可带“上次已验证”状态尝试原模型，新选项来自当前目录；提供者明确撤回模型时引导重选。
2. 将连接准备放进正常发送路径。按需启动 ACP、初始化、准备新会话/恢复本书会话、核对模型与工具就绪。连接测试走同一准备链，但标记为 test 并单计，不让测试成为运行前提。可试验**零 prompt**预热，必须证明改善首次延迟、空闲可回收、未发测试生成；没有收益就用按需启动。助手只复用本书同模型会话，普通扩写与检索继续使用隔离单轮上下文。
3. 每个用户请求持操作 ID、父 ID、来源快照、总截止和取消信号。队列、目录、初始化、建会话、首字、工具、生成、清理均消费剩余预算。记录 `promptSent`，仅在明确未发 prompt 且失败可恢复时重建一次。已提交生成、工具写记忆或送达不明的请求交给用户决定是否重试。取消时先撤队，再中止运行中的 RPC/worker/内部任务，等待本客户端旧进程树回收后允许重建。
4. 用同一阶段错误模型呈现“等待本机进程 / 获取模型目录 / 建会话 / 上游繁忙或限额 / 检索查库 / 已取消”。本机日志白名单只记耗时、阶段、错误码、模型、是否冷启动、是否发送、队列长度与是否降级。禁止将 stderr、模型原始输出尾部、提示、书名、查询和凭证写入诊断导出。保留 503、429 的分别说明。按每次调用指定模型与来源担责。
5. 使用公平且有界的启动队列。父助手在等待工具时释放可共享的初始化资源，独立检索子请求可执行；停止 A 不影响并发的 B。按书工作区空闲时关闭自己创建的进程/服务，保留可续用的会话标识。工具握手绑定当前传输代次，旧进程 tools/list 不满足新握手。当前失败统一清 session 的做法改为按阶段决定，发送前的目录错误不应损坏可恢复会话。

**完成条件**　冷启动直接选已保存模型，从三个真实功能入口发送合成请求。对比“不去设置 / 只刷新目录 / 明确测试后发送”三组，记录目录次数、建进程次数、首个有效输出、用户总等待。正常首次调用可直接完成；上游故障可解释、可取消、草稿可恢复。新旧模型交错与父助手委托检索无死锁或重复发文。

### 第三阶段　改善长任务与界面操作

- 嵌入请求从排队起即可中止。共享启动使用独立等待者，最后一名离开时才按策略回收本次启动。预热与用户请求走同一调度，记录 Vulkan 就绪、CPU 回退和模型卸载后的冷启动。构造进程假活、无 ready、回环连接重置、已收到响应头后断流，均需能退出并恢复下一次，关键词结果对作者可见。
- 把助手的工作区持久化、受限工具路由、检索任务、传输和 UI 状态分别收在有清楚入口的模块。保留现有文件格式，历史用原子替换并串行化写入，首屏/翻历史按需读。轮询先收紧为最多一个在途，再评估 IPC 推送。只向活跃视图做重 Markdown 布局，非活动视图保留草稿、滚动和任务。输入法组字、编辑记忆、停止时的草稿与未完成回复都要回归。
- 对实际闪烁录帧。覆盖普通按钮、深色打开、设置切组、长文离开写作、侧栏拖动、卡片→证据→返回、工具活动期间切页。记录 pointerdown、保存/IPC、下一次有效绘制、页面错误与可见白/空帧。深色首帧从原生窗口和页面首屏同时对齐保存的主题。导航等待确有脏稿时立即给按压反馈并等待存妥；量测到重复保存再做去重。避免全应用重新挂载或清空已有结果来显示加载。
- 将备份/恢复性能与原创检索放在独立变更中。重试复制或转移校验线程前，用临时副本模拟磁盘空间不足、文件被占用、第二个库换入失败，确认可完整回滚。单独评估索引构建与日常查库的竞争。

### 第四阶段　保持代码一致并交付

优先围绕**同一行为有多个实现**来拆模块。保留 Electron 主进程单写者、KB v2 独立库、现有业务服务和 IPC 白名单。把通用模型目录、截止/取消/诊断、只读检索三处收拢，扩写的选区和采用逻辑、检索的候选筛选、助手的记忆与工具各自保留。整理含多段状态变更的一行函数，故障注入覆盖后每次提取一个职责。写作保存和备份恢复独立审查。旧 v1、旧导入和建库脚本标注入口与适用版本，继续走现有兼容测试。

把每阶段拆成独立可撤销提交。提交说明附触发条件、改前/改后记录、诊断样例与回滚范围。若新 worker 打包失败，应可关闭该功能并明确显示原因，避免静默退回主进程全扫描。若 CLI 调度有回归，回退程序提交和版本即可；原始两库、按书历史、模型与配置不因本方案做格式迁移。正式发布按项目清单，正常退出、备份、先隔离安装、验原稿及资料摘要后，再按作者当次授权升级。[发布清单](../../release-checklist.md)

## 建议的验收表

以下阈值是同机隔离验收的**建议目标**。先保留基线再比较。P95 是将样本按耗时排序后约 95% 所在的位置。上游生成时间单列，客户端负责显示进度、接受取消、避免重复生成。

| 范围 | 合成场景与操作 | 通过条件 |
| --- | --- | --- |
| 本地检索 + 写作 | 至少让一次扫描持续 2 秒；三个入口分别跑；每 50 ms 从 renderer 发轻量 IPC，同时输入、保存、切页 | 每入口至少 100 个有效采样，建议 IPC P95 ≤ 100 ms、最大 ≤ 500 ms；扫描期间真的收到心跳；建议取消反馈 ≤ 250 ms、任务释放 ≤ 1 秒。重开原稿字节一致 |
| 反重力三用途 | 每用途冷/热成功、目录超时、建会话锁、首次无输出、有输出后断流、503/429、队列取消、恢复后再发 | 模拟环境每故障至少 3 次可重复。排队取消或配置过期后发送数 0；成功后只发送计划内的 prompt，送达不明时自动重发数 0。每次能定位失败阶段，父子时间线可关联 |
| 助手长任务 | 两书同问题、上一回合 jobId、20 个未完成再提交、失败领取、权限询问取消、切入口、卸载和恢复 | 跨书/回合拒收，running 有实际任务，done 领取后才可称完成，失败说明可见；185 秒合成延迟仍可领取。切换后仅本书数据，退出无本应用持有的孤儿 |
| 结果与证据 | 小型黄金库，限书、封存、零候选、13～18 条分页、第二修订同段号、封存/恢复后翻页、embedding 故障 | 保留命中顺序和同版证据，陈旧请求显式失效；翻页不调用外部 AI；两种降级分别可见；空选不会全部放行 |
| 按钮和长聊 | 相同机器、窗口、亮/暗主题，用 0/200 条历史、长章节和空闲/检索中两组，各做至少 30 次相同点击 | 记录 P50/P95/最大值与最慢动作录像。建议可见反馈 P95 ≤ 100 ms，无意外整窗白/空帧，0 页面错误。保留滚动、选区、IME、撤销、草稿与焦点 |
| 资源及恢复 | 重复切 10 本合成书、取消/重试 20 轮，索引/恢复期间停任务 | 报告 worker/CLI 个数、队列长度、主进程 RSS 增量和回落，退出只回收本应用所有的子树。库切换时旧 worker 不再读旧句柄，双库完整性与助手文件核对通过 |
| 真实模型抽验 | 项目允许范围内，用新造作品和固定句分别做三用途首次与连续使用；明确测试调用会用账号额度 | 记录模型、环境、时间、阶段和样本数，不以固定句成功代替委托检索。上游拒绝或不可测记实际状态；任何真实书稿或私人会话外发须有对应授权 |

Sol 先运行 `npm run build`、`npm test`，随后选用已有的 `qa-writing-regressions`、`qa-expansion`、`qa-retrieval`、`qa-assistant-experience`、`qa-assistant-layout`、`qa-readability` 和安装版 smoke。既有脚本位于 `scripts/qa-*.mjs`。新增普通入口大库端到端、CLI 阶段故障注入和按钮录帧三项，各存证据到独立 QA 目录。问题复现先写失败断言，再修改代码。只调整测试超时、降低召回上限或换更小的库，不能算达标。

## 技术路线和复用取舍

| 可复用来源 | 能解决什么，以及本项目怎样采用 |
| --- | --- |
| Electron 官方性能指南 | 指出主进程长时 CPU 工作应移出并避免同步子进程和 I/O。项目已有独立、可打包的 Node worker，可直接扩展，无需新增运行时。[Electron Performance](https://www.electronjs.org/docs/latest/tutorial/performance) |
| p-queue | 原生 ESM、MIT，维护者说明功能完备。适用于队列、优先级、取消；库内运行超时从出队才计时。先用现有队列封装满足本项目的截止时间与进程回收，若多用途公平性复杂再取固定版本，用本项目 Node 与安装包验证。引入时保留许可证。[项目 README](https://github.com/sindresorhus/p-queue) · [许可证](https://github.com/sindresorhus/p-queue/blob/main/license) |
| 官方 ACP TypeScript SDK | 官方持续发布的协议实现，可比对 stdio 分帧、能力协商和取消。项目还有反重力选模、会话恢复、状态行与 Windows 子树回收，建议本期保留现有适配器，先做同一模拟协议对照。将来替换前核对所选版本、CLI 实测能力及 Apache-2.0 分发要求。[官方 SDK](https://github.com/agentclientprotocol/typescript-sdk) · [许可证](https://github.com/agentclientprotocol/typescript-sdk/blob/main/LICENSE) |
| sqlite-vec | C 实现、支持 Windows，仓库提供 MIT/Apache-2.0 许可，仍在 v1 前迭代，同时有稳定与预发布版本。仅当移出主线程后查询本身仍慢，才在隔离副本比较耗时、召回、磁盘成本、两版证据与 Electron 的扩展加载/打包兼容。主方案直接复用已有向量 BLOB。[项目和许可](https://github.com/asg017/sqlite-vec) · [发布记录](https://github.com/asg017/sqlite-vec/releases) |
