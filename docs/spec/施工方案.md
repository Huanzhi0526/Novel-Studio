## 明确不做

不做内置拆书引擎、拆书包导出、拆书任务面板、外部 Agent 调度、生成式聊天、自动续写、原创正文自动分析、复杂关系图、账号权限、云同步、安卓端和下载采集器。对话框外观不改变“只返回检索结果”的职责。不得将作家助手或橙瓜码字的所有功能视为本项目需求。

# 一 使用流程与页面

## 原创写作

启动后进入作品列表；选择作品进入写作页。左侧是分卷章节与创作资料，中间是纯文本编辑器，右侧可展开检索侧栏。支持新建、重命名、排序、删除和恢复章节；大纲、人设、设定使用普通文档，避免另建复杂实体编辑系统。

正文编辑支持撤销重做、当前章查找替换、字数统计、自动保存和专注模式。整书检索与替换不列为首版要求。原创 TXT 导入可先作为单章，后续由用户手动拆分，不引入自动识别章节的 AI 功能。导出单章或整书 TXT，整书按卷章顺序加入标题。

## 对话框式检索侧栏

用户输入自然语言问题，显示一条用户消息；系统随后添加结果消息，包含命中卡片、作品、类别、命中摘要及“查看原文”。支持加载中、无结果、失败、取消和重试。侧栏可收起，收起不丢失本次会话的输入与结果。

工程默认：每次提问独立检索，不推断“他”“刚才那本”等指代；消息区提示“请写明人物或作品，每次独立搜索”。不调用模型改写问题，不自动把原创正文送入检索。消息历史仅当前会话保留，可清空；跨启动历史后置。这是可调整的低成本交互默认，不是生成式对话能力。

结果先展示前 10 张，支持加载更多；可按作品与卡片类别筛选。筛选在召回阶段生效，不能仅在最终前 10 条上过滤。侧栏与独立参考页共用检索服务，显示同一查询的相同结果。

## 原文阅读与知识卡管理

阅读器展示标准化正文、卷章目录、插图和可识别注释链接，统一字体及版式，不还原原 EPUB 的复杂排版。点击证据定位到对应正文版本及段落，突出显示证据范围，并可返回卡片。多段证据分别列入口，不把不连续范围误合成连续引用。

卡片允许手工修改标题、内容、分类和引用；保存前重新校验引用。已有卡片保持可用，再次导入的变化进入差异确认，不能覆盖手改。合并采用用户编辑合并结果的方式，不做自动 AI 合并。

# 二 两条独立数据链路

## 原创链路

作品 → 分卷 → 章节正文与创作资料 → 自动保存及历史 → 简单标记 → TXT 导出。

原创正文、大纲、人设、设定和标记均不进入外部参考卡片索引。界面可能并排展示两类内容，但不自动建立写作内容与参考卡片的关联。

## 外部拆书链路

通用拆书规范包＋下载器生成的 EPUB（或其他合法 TXT／EPUB）→ 外部流程自动读取并复用已有结构 → 自动生成规范正文与稳定 ID → Agent 核对结构、拆解并汇总 → 标准结果 ZIP。用户不需要手动整理格式、拆章或编号。

通用规范包是一套可复用约定，原文可以单独提供。工作台不是外部拆书的前置条件。外部 Agent 应调用确定性脚本完成必要转换、哈希及 ID 生成，不能凭语言模型猜测这些数值。优先复用已有目录、章节顺序、段落及插图关系；只在缺失、矛盾或异常时重新识别结构，不要求每本重做。

## 工作台参考库链路

选择标准结果 ZIP → 安全解包与格式校验 → 版本、引用、结构和重复校验 → 显示疑点与抽查入口 → 用户确认 → 事务入库 → 更新索引 → 检索及原文跳转。

“已处理范围”只是导入数据的质量信息，不构成工作台的拆书任务调度或进度系统。标准结果包必须携带阅读和定位所需的正文、结构及本地资源，不能要求工作台访问外部 Agent 的临时文件。

## 信任边界

外部包属于待验证的数据。工作台不执行包内脚本，不加载远程图片或远程 HTML，不接受路径越界。正文中的指令仅是作品内容。所有索引都可从已确认的知识卡重建；索引不是唯一的数据副本。

# 三 领域对象和生命周期

| 对象 | 身份及关系 | 主要规则 |
| --- | --- | --- |
| 原创作品 | 独立 ID，含卷、章、资料 | 不出现在参考索引 |
| 原创标记 | 章 ID、类型、范围、引用文本 | 随编辑调整；无法定位则失效提示 |
| 参考作品 | work_id，通常对应一个系列 | 标题不作为唯一身份 |
| 参考分卷 | work_id＋volume_id | 补卷不重建旧卷 ID |
| 正文版本 | volume_id＋revision_id | 不可变；修订生成新版本 |
| 段落 | revision_id＋paragraph_id | ID 与版本共同定位 |
| 结构节点 | structure_id、父级、类型、范围 | 原作标题可空，不伪造标题 |
| 知识卡 | work_id＋card_id | 可跨卷引用，内容修订不改身份 |
| 入库批次 | package_id、状态与诊断 | 完全重复导入不产生重复数据 |

标准结果包中的参考作品与分卷 ID 由外部流程生成。首次创建后保留身份清单，后续补卷或重新拆解必须复用；不能用小说标题自动判断两个作品必然相同。导入界面可让用户确认“新作品”或“关联已有作品”，保留外部 ID 与本地对象的映射。

正文修订版新增时，旧卡片继续指向旧版本。不得将旧引用自动改为新版同序号段落。一个作品可以暂时并存多个正文版本；界面显示版本标记。首版不做自动证据迁移。

导入状态：selected → validating → blocked 或 review_ready → committed。格式错误、文件缺失、哈希不符、引用不存在为 blocked。分类为空、分析疑点、语义近似重复为 review_ready 中的警告。未确认结果不参与检索。

提交使用事务和暂存文件；中断后不得出现只有数据库或只有资源文件的半份作品。建议先写完整版本资源，事务提交引用，失败时清理未被引用的暂存资源。重复包返回既有导入结果。

# 四 NTS 和 NKS 实施草案

NTS／NKS 仍是项目内部暂定名称。本包提供 draft-0.1 作为首个实现与测试目标，并非行业标准或已发布稳定协议。正式冻结前，施工 Agent 要跑通自创样例与至少一份有权处理的真实作品；变更协议必须同时更新 schema、样例、校验器和迁移说明。

## NTS 标准化正文

UTF-8、LF 换行、Unicode NFC。保留作品文字及有效段落边界，不做繁简转换或润色。空行用于识别段落，不作为正文段落对象；每个非空标题、正文段落、注释或图片形成一个有序 block。TXT 编码不确定时必须报疑点，不默默用乱码生成正文。

EPUB 提取以阅读顺序为主，优先复用有效目录、章节边界、插图和可识别注释目标。Agent 核对已有结构，仅对缺失或异常部分进行语义识别；不能只用正则，也不能推定下载器目录一定准确。区分卷、章、序章、尾声、幕间、后记和场景分隔，场景不自动升格为章。

每卷标准正文是一个独立对象，随 result.json 的 volumes 数组交付。revision_id 为该卷 normalized_payload 的 SHA-256；计算采用 JSON 紧凑序列化、固定字段顺序、UTF-8、不转义非 ASCII 字符，详见规范包。paragraph_id 为 p000001 起的六位最小宽度顺序号。正文版本不同则引用不同，即使局部段号相同也不混用。

chapter 结构和卡片不参与正文版本哈希；修改章节边界不改变正文 ID。图片内容哈希写入正文 payload，因此换图构成正文版本变化。原始文件的哈希独立记录，不与标准正文哈希混为一谈。

## NKS 知识卡

类别包括 character、setting、power_system、organization、event、storyline、location、item、technique。重点是前六类；地点物品适量，技巧少量且有明确证据，不为填模板造卡。空分类需由报告区分 absent、not_processed、uncertain。

最小卡片包含 card_id、category、title、content、claim_type、evidence。claim_type 取 fact 或 interpretation；混合内容应拆卡或明确整卡为分析推断。证据必须引用存在的卷、正文版本及段落闭区间。故事线可跨卷多段引用。

aliases、related_card_ids 是可选字段，用于检索别名与轻量关联，不要求关系图。关系只能指向本包或同作品已入库卡片；缺失目标先警告，不伪造目标。

# 五 导入校验和冲突

| 检查 | 阻断或处理方式 |
| --- | --- |
| ZIP 路径越界、符号链接、可执行文件 | 阻断；限制文件类型与解压后总量 |
| 未知协议版本或缺文件 | 阻断并说明支持的版本与缺失路径 |
| 文件摘要或正文 revision 不符 | 阻断，不替包改哈希冒充正确 |
| 不存在的段落或区间逆序 | 阻断，并定位卡片、字段与引用 |
| 同级章节交叉、父子范围越界 | 阻断；正常卷章嵌套允许 |
| 段落未归属正文结构或非正文分类 | 阻断；外部结果显式归类后重交 |
| 同一批重复 card_id 且内容冲突 | 阻断，不能任选一个 |
| 同包／同卡内容完全重复 | 跳过，显示计数 |
| 已有卡片内容变化 | 展示差异，用户保留、接受或手工合并 |
| 疑点、推断或近似重复 | 提醒审核，不能自动认定事实错误 |

首版采用“结构性错误阻断整批”以避免部分写入带来的复杂度。用户确认的有效批次整体提交；卡片冲突可先全部选择保留现有版本，再提交新增内容。未解决冲突时不能提交该批，但旧库照常可用。这是工程默认，需在导入界面明确提示。

抽查入口至少可查看一张人物卡、一张事件或故事线卡，以及一张分析性卡片；若某类为空则跳过，不要求凑数。确认按钮记录用户已查看诊断，不宣称人工检查了每张卡。

章节覆盖、Agent 声明的处理范围和知识卡覆盖是三件事。没有逐段卡片不构成错误。部分拆解结果可以合法导入，但必须带完整的所引用正文版本、对应结构，以及真实的未处理范围声明。

标准资源删除采用确认及软删除：隐藏作品后不参与检索，恢复后可重建索引。永久清理需显式确认；不能删除仍被其他卡片引用的共享资源。首版优先按作品归属资源，避免跨作品共享存储带来的复杂度。

# 六 原创保存和标记

工程默认：停止输入 800 毫秒后保存，并在切章、失焦及关闭前尝试刷新；显示“保存中／已保存／保存失败”。失败时保留内存内容并提供 TXT 导出，禁止显示已保存。启动时恢复未完成编辑的临时记录。

章节历史建议每 5 分钟有改动时或关闭章节时生成一份，每章保留最近 20 份；数值先作为实现默认，不做复杂策略面板。删除章节进入回收区，可恢复。只备份当前文件而无外部副本，不能称为抵御磁盘损坏的备份。

标记类型为伏笔、铺垫、关键句及其他，附可选备注。数据保存章 ID、UTF-16 起止偏移、选中文字、前后短上下文。普通编辑优先使用编辑变更映射调整范围；标记文字被删除或无法唯一重定位时标为失效，供用户重选，不自动移到相似段落。

本机默认数据目录位于用户本地应用数据目录，设置页只提供“打开资料目录”“导出备份”和基础显示设置。备份包括原创、历史、标记、参考正文、卡片和数据库版本；模型权重与可重建索引不必纳入。导出前创建一致性数据库快照，校验后原子完成 ZIP。

不做恢复中心，但必须有简单的备份恢复入口或明确的一步离线恢复工具；恢复前保留当前资料副本，校验版本后整体恢复。数据能导出却无法验证恢复，不算完成。

# 七 技术主案与验证门槛

以下为工程主案，不是用户指定技术，也未在本机实测。施工从 T00 开始验证，通过后锁定具体版本和依赖；不得把本节当作性能保证。

| 层 | 主案 | 选择理由与验证点 |
| --- | --- | --- |
| 桌面与界面 | Electron、React、TypeScript | 本机窗口及文件访问，验证安装打包与资源占用 |
| 原创编辑 | CodeMirror 6 纯文本 | 验证中文输入法、撤销、范围映射；不做代码编辑界面 |
| 存储 | SQLite，应用服务层单写入队列 | 数据事务、迁移、备份及隔离 |
| 关键词 | FTS5＋中文切词预处理 | 人名别名、短词、繁简查询，不能仅凭默认 tokenizer 合格 |
| 语义 | Qwen3-Embedding-0.6B 优先候选 | 官方支持 Sentence Transformers；型号、精度与部署经实测冻结 |
| 推理运行 | 独立本地 Python worker | 通过标准输入输出交换结构化消息，不暴露公网服务 |
| 向量 | 每卡向量持久化，内存矩阵余弦检索 | 先测个人规模，避免先引入向量数据库服务 |

worker 使用固定版本的随应用管理的运行环境，不能修改用户全局 Python。初次获取模型可联网且显示下载位置与进度；安装模型后日常查询本地运行。不依赖用户手工启动多个命令行窗口。若打包体积或显存开销不可接受，T00 比较较小的本地推理运行方案，并记录选择，不能擅自改为云端 API。

Electron 渲染层关闭 Node 集成，开启上下文隔离，通过白名单 preload 接口访问业务服务。所有文件访问与数据库操作在受控服务层完成，查询参数不拼 SQL。官方安全建议见来源 S1。

本机只读核实为 Ryzen 7 7735H、可见内存约 15.24 GiB、RTX 4060 Laptop 8188 MiB 专用显存，Windows x64。硬件信息只用于制定验证范围，不代表资源始终空闲。

## T00 通过条件

干净启动应用；中文输入及保存正常；SQLite 原生依赖在安装产物中可用；embedding worker 可加载、退出和故障恢复；至少 30 条中文查询完成检索；记录冷启动、热查询、内存、显存、依赖和安装体积。缺少真实样本时先用自创样例做机制验证，但真实检索验收不得省略。

# 八 检索实现和验收

索引对象仅为已确认外部卡片的标题、别名、正文和类别；证据正文不自动整本切片入索引。Embedding 输入模板固定并版本化，卡片修改后仅更新相关向量；切换模型、维度或模板必须重建对应索引。

关键词和语义分别取候选，再按 card_id 合并。首个融合方案使用 RRF，参数 k=60，两路权重相同；不把原始关键词分数与余弦相似度直接相加。该参数是起点，需在查询集上验证。结果摘要来自已存卡片，不由生成模型改写。

关键词召回需覆盖中文词语、人名及别名；对短词保留精确子串补偿。繁简归一化仅用于检索字段和查询副本，不改正文或证据。候选切词库及索引策略在 T00 记录，不能未经测评增加额外大型依赖。

无关键词命中不必等于无语义命中；语义结果也不能永远强行返回最相似卡片。使用含无关问题的查询集校准语义阈值，未达到阈值显示未找到。界面不展示“事实可信度百分比”。

## 建议验收集与目标

使用 50 部作品、最多 5 万卡作为工程压力场景，不是产品硬上限。额外构造单卷 300 万中文字的阅读样本，验证分页读取和定位；该体量是测试建议，不代表用户已声明最长作品。

准备不少于 30 条人工标注查询，包含精确名称、别名、设定、情节意图、跨卷故事线和至少 5 条无答案问题。可回答查询至少 80% 在前五条找到人工认可结果；无答案问题至少 80% 不返回误导结果。规模较小的验证集应报告具体条数，不能仅报比例。

性能目标为正常后台负载下热查询 P95 不超过 2 秒、阅读跳转不超过 1 秒；记录测量数据和异常条件，未达到时分析瓶颈并提出取舍，不能静默降低标准。模型故障时降级为关键词检索并提示；此降级不等于完成混合检索验收。

# 九 模块和调用契约

| 模块 | 输入与输出 | 不负责 |
| --- | --- | --- |
| WritingService | 原创文档变更、保存版本、标记 | 参考索引及 AI 处理 |
| ImportService | 结果包路径 → batch_id、诊断、差异 | 拆书、补写卡片、纠正包内容 |
| ReferenceService | 作品、版本、卡片的查询和手改 | 原创资料混合检索 |
| SearchService | 查询及过滤 → 卡片结果、耗时、降级状态 | 生成回答、自动指代消解 |
| ReaderService | 作品／卷／版本／段落 → 阅读窗口 | EPUB 复杂样式还原 |
| BackupService | 导出／恢复请求 → 校验报告 | 云同步和计划任务 |
| EmbeddingWorker | 文本批次 → 向量及模型信息 | 文本生成、数据库直接写入 |

内部调用采用类型化对象。统一错误包含 code、message、recoverable、details；details 可带文件、字段及对象 ID，但不得包含任意原文全文。日志默认记录诊断元数据，不记录原创正文。

核心接口草案：import.inspect(path) 返回诊断与冲突列表；import.commit(batchId,resolutions) 原子提交；search.query(query,workIds,categories,limit,cursor) 返回结果；reader.locate(workId,volumeId,revisionId,start,end) 定位；writing.save(chapterId,expectedRevision,text) 防止旧保存覆盖新内容。

长任务使用 request_id 可取消。取消仅取消本次查询或导入准备，不损坏已提交数据。UI 不直接访问数据库和任意文件路径。结果分页须绑定相同查询及索引代次，索引变化时提示重新搜索。

数据库建议分别使用 original_* 与 reference_* 表，建立明确外键；不强求两个数据库文件。段落按版本索引、卡片证据为多对多关联。向量带 card_id、card_revision、model_id、template_version，防止新正文配旧向量。

## 必须覆盖的异常测试

错哈希、错 ID、错版本、跨卷非法引用、章节交叉、空分类、分批结果、重复包、冲突 card_id、手改后重导、超长正文、缺图片、恶意 ZIP 路径、导入中断、保存失败、索引落后、模型未安装和模型崩溃。

# 十二 下载器产物复用与外部转换

## 用户实际操作

使用 wenku8-downloader 下载有权使用的作品后，将 EPUB 与通用拆书规范包交给外部 Agent 即可，不需要手动修正文格式，也不需要先打开工作台。外部流程完成必要转换、拆解和打包后，用户只向工作台导入标准结果包。

## 两条输入路线

默认路线是 EPUB：复用目录、阅读顺序、段落和图片引用，经自动转换生成 NTS 草案要求的正文和稳定 ID，再进行拆书。下载器产物格式统一只能减少转换复杂度，不能替代本项目的版本与证据引用契约。

可选路线是下载器结构化工作区：book.json、chapters 和相关 assets。只有开发 Agent 检查过实际版本与样本后才实现直接适配；不要求用户为此提供 Cookie、登录配置或整个用户目录。适配失败或版本未知时优先回到 EPUB 路线。

## 外部转换工具交付

T01 需要交付可重复运行的外部转换工具，随拆书规范包提供，不集成进工作台。输入为 TXT／EPUB 及可选既有作品身份清单；输出为 NTS 正文、段落索引或可派生索引、结构候选、资源清单及诊断，供 Agent 继续拆解。工具不负责生成知识卡。

第一次转换生成并保存 work_id 和 volume_id；重跑须复用身份清单。在相同身份、源内容和转换规则下，输出正文哈希及段落 ID 必须一致。不得通过每次随机生成卷 ID 破坏可重复性。转换规则变更应标注工具版本，并解释正文版本是否变化。

## 验收和异常处理

至少验证：带目录和插图的 EPUB、已有序章与后记的 EPUB、目录缺失或异常样例、普通 TXT、同输入重复转换。检查文字与段落保留、卷章顺序、插图和注释对应、证据跳转及结果可重复性。自创 EPUB 可验证机制，至少一份实际下载产物仍须由用户合法提供或授权获取后复核。

正常样本不要求用户逐章整理。遇到无法解码、源文缺失或目录冲突时由工具给出可定位诊断，Agent 尽量自动处理；只有无法可靠解决的疑点才请用户判断。不得在缺文时猜写正文。

下载器结构化工作区适配为可选项，EPUB 自动转换是标准路径。这个调整不要求在工作台增加下载器、采集器、预处理面板或拆书按钮。NTS／NKS draft-0.1 的输出契约保持不变，本版修改的是输入处理与职责说明。
